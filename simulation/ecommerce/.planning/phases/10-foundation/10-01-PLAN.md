## Objective

Implement the complete user authentication system for ShopNova: user registration, login, JWT token management, and structured error handling. This plan covers AUTH-01 through AUTH-04 and establishes the foundational data model, database connection, and validation patterns that all subsequent phases depend on.

## Context

This is the first plan in Phase 10 (Foundation). There are no prior implementations to build on — we are creating the project's data layer and auth system from scratch. The tech stack is Next.js 16 App Router with Prisma 7, PostgreSQL, bcryptjs for password hashing, jose for JWT signing/verification, and Zod for request validation.

<action>
Create three Next.js App Router route handlers:

POST /api/auth/register (register/route.ts):
1. Parse body with registerSchema
2. Check for existing user by email — return 409 {error: {code: "EMAIL_EXISTS"}} if found
3. Generate UUIDv7 for user ID
4. Hash password with hashPassword (cost 12)
5. Create user via Prisma
6. Return 201 with {id, email, createdAt} — never return passwordHash

POST /api/auth/login (login/route.ts):
1. Parse body with loginSchema
2. Find user by email — return 401 {error: {code: "INVALID_CREDENTIALS"}} if not found
3. Verify password — return 401 {error: {code: "INVALID_CREDENTIALS"}} if wrong
4. Sign JWT access token (15-min) and refresh token (7-day)
5. Return 200 with {accessToken, refreshToken, user: {id, email}}

POST /api/auth/refresh (refresh/route.ts):
1. Parse body with refreshSchema
2. Verify refresh token — return 401 {error: {code: "TOKEN_EXPIRED"}} if expired
3. Look up user by sub claim — return 401 if not found
4. Issue new access token
5. Return 200 with {accessToken}

All routes must:
- Use Zod validation at the entry point
- Return structured errors: {error: {code: string, message: string}}
- Handle JSON parse failures gracefully (400)
- Never expose internal error details to clients
</action>

</verify>
<done>
All three route handlers compile. Registration creates users, login returns JWT tokens, refresh issues new access tokens. Error responses follow the {error: {code, message}} structure for all failure cases.
</done>
