Execution Modes
🐳 Container Mode (Docker)
Isolated Docker containers. agent-entrypoint.js reads agent.json, copies repo, applies patches, invokes claude --print. Best for production use.
🌿 Worktree Mode (fallback)
Git worktrees + Claude CLI subprocess. No Docker required. Same concurrency limits. Drop-in replacement.
⚡ Sequential Mode
Weak machine mode. One agent at a time. No parallelism. Used when resources constrained.

4 Agent Archetypes
🎯 Specialist
When: Single module, strong capability match
Behavior: Deep focus, assumes domain context, minimal cross-module awareness
Verification: Module-specific tests only
Time: 2–5 min
🔗 Integrator
When: 3+ modules touched, cross-boundary work
Behavior: Interface-aware, extra caution at module boundaries, coordinates between services
Verification: All touched modules' test suites
Time: 4–8 min
⚠️ Careful
When: High/critical risk score (auth, payments, migrations)
Behavior: Extra verification steps, conservative approach, detailed logging, rollback planning
Verification: Full 8-layer pipeline
Time: 5–10 min
⚙️ General
When: Fallback when no other archetype matches
Behavior: Balanced approach, standard verification, follows plan literally
Verification: Plan-defined + graph-detected
Time: 3–6 min
Context Package Composition (Step 4)
always_load (mandatory)
Plan.md + task files directly referenced. Always in context window.
task_specific (graph-driven)
Dependencies, consumers, test files for changed code. From graph context-for-task query.
reference (interface context)
interfaces.yaml for touched modules. Neighbor service interfaces (multi-repo). Architecture docs if brownfield.
Total budget: 70% of context window (140k of 200k tokens)

Verification Engine — 8-Layer Pipeline + Auto-Fix Loop
forge-verify/engine.js — graph-aware, fail-fast verification with automatic repair
8 Verification Layers (Fail-Fast Order)
L1
STRUCTURAL
<5s
Syntax errors, stray console.log/debugger, merge conflict markers, bracket balance
L2
TYPE / COMPILE
10–30s
tsc --noEmit (broad tsconfig discovery) | mypy | go build. Override: type_check_command config
L3
INTERFACE CONTRACTS
5–15s
Graph contract_hash comparison. Breaking change detection. High-consumer export risk (fan-in)
L4
DEPENDENCY
<5s
graph.getCycles() — new circular deps. Orphaned imports. Module boundary violations.
L5
TESTS
30s–5min
Graph context-for-task → identifies test files for changed code. Runs npm test (or override). Timeout configurable.
L6
BEHAVIORAL
varies
Plan's custom verify steps from frontmatter. Shell commands. Fail-fast on first failure. NOT auto-fixable.
L7
CONTRACT
5–30s
Code↔YAML drift. Backward compatibility vs baseline. Cross-repo ripple via system-graph.db. Requires interfaces.yaml.
L8
ARCHITECTURAL (off by default)
LLM call
Agent reviews against ARCHITECTURE.md + CONVENTIONS.md. Enable: verification.layers.architectural = true

Auto-Fixable Failures
L1 — Syntax Issues
Stray debugger/console.log, bracket mismatches
L2 — Type Errors
Missing type annotations, wrong types
L3 — Interface Breaks
Signature mismatches, missing exports
L4 — Missing Imports
Orphaned imports, circular deps
L5 — Assertion Mismatches
Test expectation drift from impl changes
L6 — NOT Auto-Fixable
Behavioral failures require human judgement
Loop Prevention
Same patch hash twice → stuck → escalate

Fix introduces NEW layer failures → revert → escalate

Max loops exceeded (default 3) → escalate
Wave vs Full Verification
verifyAfterWave (quick)
Layers 1–4 only. Max 2 loops. Runs after each wave completes.
verifyFull (complete)
All 6–8 layers. Max 3 loops. Runs after all waves complete.

Warnings

Preferences

Rejected Approaches

Key State Files — The Control Triad + Supporting
PROJECT.md
Vision, decisions, requirements summary. Updated by /forge:new-project and /forge:new-milestone. Human reference + agent context.
ROADMAP.md
Phase breakdown, REQ-ID mapping per phase. Updated by add/insert/remove-phase. Controls what gets planned and executed.
STATE.md
Living memory: current position, recent decisions, blockers, todos. Updated after every phase. Used by all workflows for orientation.
REQUIREMENTS.md
Canonical REQ-IDs with traceability, status, acceptance criteria. Archived on milestone complete.
CONTEXT.md (per phase)
User decisions from /forge:discuss-phase. Locked constraints for planning and execution agents.
SUMMARY.md (per plan)
Phase completion report, deliverables, requirements satisfied. Source for /forge:verify-work UAT tests.
